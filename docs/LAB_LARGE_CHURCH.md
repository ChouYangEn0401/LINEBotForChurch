# 🧪 實驗：大教會架構（牧區 → 區 → 小組）

> 狀態：**實驗中**。管理網頁「🧪 大教會（實驗）」目前只做到「畫出架構、估算每個單位的 LINE 則數」，
> **不會改變實際發送**。這份文件整理「如果要正式支援大教會」要想清楚的事，給之後討論與開發用。

---

## 1. 現在的程式是為「一間小教會、一份服事表」設計的

| 目前的假設 | 大教會會遇到的狀況 |
|---|---|
| 一份服事表（一個 Google Sheet 網址） | 每個牧區、每個事工各自排班，表格散在很多地方 |
| 一個發送時間 | 北區週六晚上發、青年團契週五發 |
| 一個管理員收所有通知 | 北區的名字對不到，不需要吵到南區、也不需要吵到總管理員 |
| 一份同工名單，**真實姓名**就是唯一的鍵 | 幾百人一定有同名同姓 |
| 能開管理網頁的人什麼都能改 | 小組長只該改自己小組的東西 |
| 一台常開的電腦就夠 | 要一直收集名字、多人同時使用，需要 24 小時的主機 |

## 2. 實驗頁現在做了什麼

- `config/org.csv`：一列一個「單位」，用「上層單位」串成一棵樹，**層數不限**（牧區 → 區 → 小組，或只有小組）。
- 每個單位可以掛：**LINE 群組**（LINE 群組頁上的名稱）、**同工**（同工名單上的名字或其他寫法）、負責人、備註。
- 每個單位顯示「含下層」的合計：幾個群組會收到提醒、約多少人、**每月約多少則**、幾位同工（同一個人在兩個小組只算一次）。
- 全教會估算＋建議方案（輕用量 200／中用量 3,000／高用量 6,000 則）。
- 「更新群組人數」：向 LINE 查詢每個群組人數（查詢不算訊息，不扣額度）。
- 「還沒分配」：哪些群組、哪些同工還沒放進任何單位。
- 資料有問題（上層不存在、繞圈、群組放兩個地方、名字對不到）只會列出來，不會讓頁面壞掉。

範例：

```csv
單位名稱,上層單位,類型,負責人,LINE群組,同工,備註
北區,,牧區,李約書亞傳道,北區同工群,李約書亞傳道,
北一小組,北區,小組,張志豪,北一小組,阿豪、喜樂、恩典,
南區,,牧區,,南區同工群,,負責人待定
```

## 3. 要正式支援，建議的資料模型

```
Church（教會）
 └─ Unit（單位：牧區 / 區 / 小組 / 事工團隊…，樹狀、層數不限）
     ├─ settings override（沒寫就沿用上層）：服事表來源、發送時間、訊息模板、通知對象
     ├─ targets（LINE 群組；一個群組只屬於一個單位）
     ├─ memberships（同工 ↔ 單位，多對多：一個人可以在好幾個單位）
     └─ admins（這個單位的管理員；權限往下繼承）

Person（人）
 ├─ id（內部編號，永遠不變）         ← 取代「真實姓名」當主鍵
 ├─ real_name、aliases（服事表上的各種寫法）
 └─ line_user_id（同一個 LINE Provider 底下永遠不變）
```

幾個關鍵決定：

1. **設定繼承**：全教會設預設值，牧區只寫「跟上層不一樣的地方」。改一次全教會的訊息模板，所有沒覆寫的單位一起生效。
2. **一個群組只屬於一個單位**：人數與則數才不會重複計算；需要「北區所有群組」時由樹往下找。
3. **人不屬於群組，人屬於單位**：換群組、開大群、拆群組都不用重新收集名單（這也是目前 LINE 帳號與群組分開存的原因）。
4. **主鍵從真實姓名換成內部編號**：服事表上仍然寫名字，對照時用「名字＋單位」縮小範圍，同名同姓才分得開。
   目前 `members.csv` 以名字為鍵，遷移時要幫每個人產生編號。

## 4. 權限與通知

| 角色 | 看得到 | 改得到 | 收到的通知 |
|---|---|---|---|
| 總管理員 | 全部 | 全部 | 全教會層級的問題（LINE token、額度、主機） |
| 牧區管理員 | 自己牧區（含下層） | 自己牧區的設定、群組、名單 | 自己牧區的問題 |
| 小組長 | 自己小組 | 自己小組的名單 | 自己小組的名字對不到、服事表快用完 |

- 網頁登入要從「一組密碼」變成「每個人一個帳號」（可以用 LINE Login，剛好用 LINE userId 對到 Person）。
- 聊天室的 `/設定` 驗證碼改成送給「那個單位的管理員」。

## 5. 費用（最容易被忽略）

- 推播到群組 = **群組人數 × 發送次數**。幾百人的教會每週推到每個小組群，很快就是每月幾千則。
- 實驗頁的估算就是為了在決定之前先看到數字。常見的省錢做法：
  1. 只推到「同工群」，不推到所有小組群；
  2. 改成每兩週一次（「設定 → 每幾週發送一次」）；
  3. **只私訊當週有服事的人**（例如每週 20 人 → 每月約 87 則），代價是每個人都要加機器人好友、Webhook 要一直開著。
- 額度是「整個 LINE 官方帳號」共用。要各牧區分開報帳，可以：一個帳號＋程式裡依單位統計用量；或每個牧區一個官方帳號。

## 6. 一個 LINE 官方帳號，還是每個牧區一個？

| | 一個帳號 | 每個牧區一個 |
|---|---|---|
| 管理 | 集中，一組 token | 每個牧區各自申請、各自保管 token |
| 額度 / 帳單 | 共用，要自己拆帳 | 天生分開 |
| 同一個人的 LINE userId | 一樣 | **同一個 Provider 底下**的 Channel 才一樣；不同 Provider 會不一樣，名單無法共用 |
| 程式要改的 | 少 | 設定要能「每個單位一組 token」 |

建議：**所有 Channel 都建在同一個 Provider 底下**，保留日後合併名單的可能。

## 7. 主機與資料

- 要持續收集名字、多個牧區同時使用 → 需要 24 小時開著、有固定 https 網址（雲端主機或固定的 Cloudflare Tunnel）。
- CSV 很適合一間教會用 Excel 改；上百個單位、多人同時編輯時，改用 SQLite（已經在用）或 Postgres 比較安全，CSV 保留成「匯入／匯出」。
- 個資：牧區之間的名單不互相看；刪除離開的人要能真的刪乾淨。

## 8. 建議的開發順序

1. ✅ **看得見**（現在）：架構圖、每個單位的群組與人數、則數估算。
2. **發送依單位分流**：`targets` 加上所屬單位；主控台預覽、發送紀錄可以用單位篩選；用量報表按單位統計。
3. **設定繼承**：每個單位可以覆寫服事表來源、發送時間、通知對象。
4. **帳號與權限**：LINE Login、單位管理員、通知分流。
5. **人員主鍵換成內部編號**，支援同名同姓。
6. **只私訊當週服事的人**（省額度的最大一步）。

每一步都可以單獨上線，前一步不會卡住小教會現在的用法。
