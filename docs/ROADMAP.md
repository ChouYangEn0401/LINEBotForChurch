# 之後想做的（備忘，目前都「還沒做」）

現在的目標是**簡單、會動、少出錯**。下面是已經討論過、但刻意先不做的東西，等真的需要再做。

## 現在的樣子（MVP）

- 每週四 20:00 自動 Push 一次（所有群組同一個時間）。發送**當下**才讀 Google Sheet，所以一定是最新的，不用每天檢查。
- 群組裡任何人打 `/提醒`：馬上用 Reply（免費）回這週的提醒。
- 排程時間到了：跟最後一次送出的內容一樣就略過（`/提醒` 只算 2 天內打的）；服事表改過就送新的。
  不管「誰換成誰」，只保證最後送出的是正確的人。
- 同工名單有 LINE_userId 的人會被 @；沒有的照樣印名字，訊息最後會請他們打 `/我的ID`、`/我的名字 XXX` 登記。

## 1. 發送前一天先「檢查」一次

例如週四發提醒，週三先跑一次**不發送**的檢查：服事表沒排、名字對不到、服事表快用完，就先私訊管理員，
讓他週四之前有時間改。

- 做法：多一個排程（`check_day`），跑 `service.run("check", dry_run=True)`，有問題才通知管理員。
- 注意：預覽（dry run）現在不寫紀錄，也不通知管理員，要另外處理。
- 成本：有問題時私訊管理員一則（個人私訊算 1 則）。

## 2. 每個群組有自己的提醒日／檢查日

例如青年團契週五提醒、主日同工週四提醒。

- 做法：`targets.csv` 加「提醒日」「檢查日」兩欄（空白 = 用全域設定）。
  排程改成「每天固定時間醒來一次，看今天有哪些群組要發／要檢查」，而不是現在的「每週一次」。
- 防重複的方式（target + 日期 + 內容）不用改。

## 3. 幾個群組共用一份 Google Sheet，不同群組用不同的表

- 做法：`targets.csv` 加「服事表」欄（網址或代號），沒填就用設定裡的那一份。
  `fetch_roster` 依網址快取，同一份表一次發送只讀一次。
