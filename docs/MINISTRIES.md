# 多牧區（牧區 → 群組）

> 一個程式、一個 LINE 官方帳號，管很多個牧區。每個牧區裡面就是原本那一整套：
> 服事表、同工名單、小團、LINE 群組、設定、發送紀錄，**各自獨立**，互不影響。

## 畫面怎麼走

```
登入（第一層：整個網站的密碼）
 └─ 首頁：所有牧區（每個牧區一張卡：幾個群組、下次什麼時候發、有沒有要處理的事）
     ├─ 青年牧區（第二層密碼：牧區自己決定要不要設）
     │   └─ 跟原本一模一樣的後台：主控台、服事表、同工名單、LINE 群組、發送紀錄、設定、變更紀錄
     │       └─ LINE 群組：每個群組可以有自己的提醒訊息（標題、結尾、整則改寫）
     ├─ 壯年牧區 …
     └─ ＋ 新增牧區
```

左上角「← 所有牧區」回首頁。王小明要幫別的牧區建系統，回首頁點那個牧區就好。

## 資料放哪裡

```
config/
  church.yaml                 牧區清單（編號、名稱、備註、第二層密碼的雜湊）＋ 網頁設定
  ministries/m1/              一個牧區一個資料夾，裡面的檔案跟以前 config/ 底下一樣
    settings.yaml  targets.csv  members.csv  teams.csv
  _before_ministries/         改版前的舊檔（搬家時留一份，確認沒問題可以刪）
data/
  church_bot.db               全教會共用：LINE 用量、對外網址、還沒分到牧區的群組、變更紀錄
  ministries/m1/church_bot.db 這個牧區的發送紀錄、防重複、在它的群組裡收集到的 LINE 帳號
```

- **牧區編號（m1、m2…）建立後永遠不變**，網址、指令列都用它；名稱隨時可以改。
- 牧區之間的名單不互通：青年牧區的管理員看不到壯年牧區收集到的 LINE 帳號。
- LINE 金鑰、網站密碼仍然只在 `.env`（整個教會共用一個 LINE 官方帳號，額度也共用）。

## 決策

| 決策 | 原因 |
|---|---|
| 兩層（牧區 → 群組），不做無限層 | 每個牧區自己就是完整的一套，要多少就加多少；不用想「哪一層的設定生效」，不懂程式的人也看得懂。真的要再分層，牧區資料夾不用改 |
| 每個牧區一個資料夾，不合併成一份 | 乾淨：搬移、備份、刪除一個牧區就是一個資料夾；一個牧區的檔案壞掉不影響別人 |
| 群組歸哪個牧區看 `targets.csv` | 跟以前一樣在「LINE 群組」頁管理；機器人新加入、還沒分配的群組先放在首頁「還沒分配的群組」 |
| 自動發送由後台內建排程，每個牧區一個鬧鐘 | 後台開著就照每個牧區自己的「星期幾、幾點、每幾週」發；不是輪詢，時間到才醒來。Telegram 的 `cli.bat send` 保留當備援，兩邊都觸發也只會發一次（防重複） |
| `cli.bat send` 不帶牧區 = 今天輪到的牧區 | 「自動發送」開著、而且發送日是今天的牧區才發；`--牧區 青年牧區` 只發那一個 |
| 兩層密碼 | 第一層是整個網站；第二層每個牧區自己決定要不要設。忘記第二層密碼只能在那台電腦本機（127.0.0.1）或用指令清掉 |
| 變更紀錄內建，不用 git、不用 DoltLite | 每次存檔記下「什麼時候、從哪裡（網頁 / LINE / 機器人）、改了什麼」，相同內容只存一份、壓縮存放；網頁上看得到前後差異、一鍵還原。DoltLite 沒有 Windows 版、要把 CSV 改成資料庫；git 要每台電腦都裝、非工程師看不懂 |
| 不記「是誰改的」 | 擁有者決定：只記時間、來源和內容 |

## 從單一牧區升級

第一次用新版開啟時自動搬家：原本 `config/` 的設定與三張表、`data/church_bot.db` 搬進第一個牧區，
原檔另外留一份在 `config/_before_ministries/`。什麼都不用重新設定，Telegram 的排程也不用改。
