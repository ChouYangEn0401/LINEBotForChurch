# LINE 的 ID、群組成員與私訊：運作原理

> 資料來源：LINE Developers 官方文件（查詢日期 2026-09-11），連結在最後。
> 這份文件回答幾個常見問題：
>
> 1. 機器人是怎麼知道群組 ID、個人 ID 的？要不要自己架一台伺服器？
> 2. LINE Developers 裡的「Provider」是什麼？
> 3. 能不能知道群組裡有哪些人？
> 4. 知道某人的 ID 之後，能不能直接私訊他？怎麼算錢？
>
> 想直接照做的操作步驟，看 [QUICKSTART_TEST.md](QUICKSTART_TEST.md)（從零開始申請＋測試）
> 或 [SETUP_LINE.md](SETUP_LINE.md)（完整設定參考）。這篇是「原理」，看懂會少走很多冤枉路。

---

## 1. 先搞懂：機器人和 LINE 之間有「兩個方向」，只有一個方向需要「伺服器」

```
① 主動發送（Push）：我們 → LINE          不需要公開網址、不需要伺服器
   本程式 ──「請把這段文字送到群組 C123…」──▶ LINE ──▶ 群組
   ・這台電腦「主動連出去」問 LINE，就像平常用瀏覽器上網一樣。
   ・每週提醒就是這個。電腦只要「開著、能上網」就夠了。
   ・會扣每月額度（群組按人數算）。

② 事件通知（Webhook）：LINE → 我們        需要一個固定、24 小時都能連到的公開網址
   有人在群組打「/群組ID」──▶ LINE ──「群組 C123… 裡的 U456… 說了：/群組ID」──▶ 本程式
   本程式 ──「回覆：這個群組的 ID 是 C123…」──▶ LINE ──▶ 群組
   ・這一次反過來，是 LINE 要「主動連進來」找你的程式，所以你的程式要有一個
     LINE 找得到的地址——這就是「需要公開網址」的原因，跟平常上網收信不需要地址是相反的方向。
   ・事件發生時，LINE 會把「群組 ID」「發話人 ID」一起告訴我們。
   ・回覆（Reply）是免費的，不扣額度；被動收到事件本身也不扣額度（見第 4 節）。
```

**所以「是不是透過 Webhook、讓機器人在群組裡發言？」——是的。**
機器人沒辦法主動「查詢」任何 ID，只能在事件發生時（有人打字、有人加入、機器人被邀請）由 LINE 告知，再用「回覆」把 ID 說出來。

### 這是不是代表我一定要先架一個網站，才能讓機器人發訊息？

**不是。這兩件事完全分開：**

| 你想做的事 | 需要固定的公開網址（＝某種伺服器）嗎 |
|---|---|
| 每週自動提醒（本程式現在的核心功能） | ❌ 不需要。教會那台電腦開著、能上網就好 |
| **第一次**抓群組 ID / 自己的 userId | ⚠️ 需要，但**只需要暫時**用一下（見下方），抓完可以關掉 |
| 一直開著、自動記錄「誰在群組講過話」（還沒做的功能） | ✅ 需要，而且要**一直**開著 |

抓 ID 只需要「暫時」的公開網址，這是因為 LINE 只有在「有人打字的當下」才會通知你——所以你只要在**打算抓 ID 的那幾分鐘**開一個臨時通道就好，不用整天開著。
[SETUP_LINE.md](SETUP_LINE.md) 第 5 步教的 `cloudflared tunnel` 就是做這件事：開啟 → 抓到 ID → 關掉，跟開瓦斯爐煮飯、煮完關火是一樣的概念，不是要一直開著的東西。

真的要「一直開著」的，只有「自動記錄群組裡每個人」這種**還沒開發**的進階功能（見第 6 節），到時候才需要考慮買雲端主機。**現在你不需要這個。**

> 💡 你可以把 LINE Developers 後台「Use webhook」那個開關**留著開**，就算 cloudflared 的臨時通道已經關掉也沒關係，
> 不會花錢也不會影響每週提醒。頂多是 LINE 後台會出現「Webhook 傳送失敗」的紀錄，那是因為找不到已經關掉的臨時網址，
> 忽略即可——「/群組ID」「/我的ID」這幾個查詢指令會失效，但跟發送提醒是兩條完全不相關的路，不會互相拖累。

### 每週自動發送的那一刻，實際上發生了什麼事（從頭到尾都沒用到 Webhook）

這是最常被誤會的地方，逐步拆開來看：

```
① 到了設定的時間（例如每週六 20:00）
   → 程式自己內部的「鬧鐘」響了，這一步跟 LINE 完全無關，純粹是這台電腦自己的時鐘

② 程式去讀 Google Sheet
   → 跟 Google 講話，也跟 LINE 無關

③ 程式在自己電腦裡對照 members.csv、targets.csv，決定要發什麼、發給誰
   → 純本機運算，沒有連任何網路

④ 程式直接呼叫 LINE 的「發送訊息」API（帶著 Channel access token 這把鑰匙）
   → 這就是最上面說的「①主動發送 Push」：程式主動打電話問 LINE「請幫我把這句話送到 C123…」
   → LINE 收到後立刻回「好，收到了」

⑤ 群組收到訊息
```

從頭到尾，**Webhook 一次都沒有被用到、也不需要它是開著的**。
Webhook 只有在「LINE 反過來要通知你」的那三種情況才會用上（見上面②的例子），跟「發送提醒」是兩條完全獨立、互不相干的路。

## 2. LINE Developers 裡的「Provider」是什麼？

申請機器人時，LINE Developers 會請你選或建立一個「**服務提供者（Provider）**」，很多人在這裡卡住。用一個比喻：

```
Provider（服務提供者）  ≈  教會這個「組織」的戶頭
  └─ Channel（管道／頻道）  ≈  一個具體的機器人／應用程式
       （這個專案只會用到一個 Channel：就是「服事提醒機器人」本身）
```

- 一個 Provider 底下可以放好幾個 Channel（例如以後想做第二個機器人，可以放在同一個 Provider 底下）。
- **這個專案只需要一個 Provider、一個 Channel**，第一次設定時照 [SETUP_LINE.md](SETUP_LINE.md) 選「建立新的服務提供者」、名稱填教會名稱即可，之後都不用再管它。
- 唯一要注意的：**同一個人在「同一個 Provider」底下拿到的 userId 永遠一樣**，但如果換成「不同的 Provider」，同一個人會拿到**不同**的 userId（LINE 是按 Provider 分開發放編號的）。
  - 白話文：**Provider 建好之後不要刪掉重建**。刪掉重建等於全部的 userId 都要重新收集一次。
  - 正常使用（重開電腦、重開程式、改設定）完全不會動到 Provider，不用擔心。

## 3. 三種 ID

| ID | 長相 | 代表 | 怎麼拿到 |
|---|---|---|---|
| 群組 ID | `C` + 32 碼 | 一個群組 | 在群組打「/群組ID」，或機器人剛被邀進群組時自動回報 |
| 使用者 ID（userId） | `U` + 32 碼 | 一個人 | 本人打「/我的ID」，或他在有機器人的群組裡講話時 |
| 聊天室 ID | `R` + 32 碼 | 舊式多人聊天室 | 同群組 |

- ⚠️ userId **不是**大家在 LINE 上設定、用來加好友的「LINE ID」（例如 `@abc123`）。userId 是 LINE 系統產生的，本人在手機上也看不到。
- **userId 是永久的**，跟這個程式、這台電腦、機器人有沒有重開機完全無關：
  - 它是 **LINE 那邊**發給「這個人 × 這個 Provider」的固定編號，不是本程式產生或管理的東西；重開機、換電腦、重新部署程式，userId 完全不會變。
  - 換人改名字、換手機、換 LINE 版本都不會變。
  - 只有兩種情況會變：① 那個人**刪掉重建 LINE 帳號**（等於變成另一個人）；② **換了不同的 Provider**（見第 2 節）。
  - 本程式只是把 userId **抄一份**存進 `config/members.csv`；就算這個檔案不見了，userId 本身在 LINE 那邊還是有效，只是要重新請本人打一次「/我的ID」再抄一次。
- 只用過電腦版 LINE、從沒用過手機版的人：LINE 不會提供他的 userId（他沒辦法同意個資授權）。手機版使用者在開始使用 LINE 時就已經同意了。

## 4. 能不能知道群組裡有哪些人？

| 想知道的 | 做得到嗎 | 說明 |
|---|---|---|
| 群組有幾個人 | ✅ 可以 | 所有帳號都能查（不含機器人自己）；本程式用它估算每次推播要扣幾則 |
| 群組**全部成員**名單 | ⚠️ 只有「認證帳號」或「優質帳號」 | LINE 規定「取得群組成員 ID」只開放給認證／優質帳號，需要向 LINE 申請審核。免費的一般帳號不能用 |
| 在群組裡講過話的人 | ✅ 可以（被動收集） | 有人在群組發言時，Webhook 會帶他的 userId（手機版使用者才有）——**不花錢**，見下方說明 |
| 機器人加入後才進群組的人 | ✅ 可以（被動收集） | 有人加入群組時，會收到「成員加入」事件，裡面有他的 userId |
| 知道 userId 之後，查他的名字 | ✅ 可以 | 「群組成員資料」可以查同一個群組成員的顯示名稱，**不管他有沒有加機器人好友** |
| 從來不講話、而且在機器人加入前就在群組的人 | ❌ 一般帳號拿不到 | 除非申請認證帳號，或請他打一次「/我的ID」 |

**被動收集會不會花錢？不會。** LINE 只針對「機器人主動發出去的訊息」按人頭計費；別人傳訊息給機器人（機器人只是「聽到」、不回應）**不算機器人發送**，不管多少人傳、傳幾次，都不會扣任何額度。
如果本程式打開 Webhook、單純把「誰在群組打了什麼」記下來、機器人完全不回應，這個動作在 LINE 這邊完全免費；**唯一可能有成本的是「host 這個能一直被連到的網址」本身**（如果用免費的臨時通道，成本也是 0，只是網址不固定，見第 1 節）。

**本程式目前的做法**：只記錄「群組」，不會自動記錄「個人」。要某個人的 userId，請他本人打「/我的ID」。
「在群組講過話就自動記下名字和 ID」這個功能做得到，只是還沒做（見第 6 節）。

## 5. 知道 ID 之後，能不能直接私訊？

**可以，但對方必須先「加機器人好友」。** LINE 的規則：

| 對象 | 私訊收得到嗎 |
|---|---|
| 已經加機器人好友的人 | ✅ |
| 7 天內主動私訊過機器人的人（就算沒加好友） | ✅（只限那 7 天） |
| 沒加好友的人 | ❌ |
| 封鎖機器人的人、刪除 LINE 帳號的人 | ❌ |

⚠️ **最需要注意的地方**：發給「收不到的人」時，LINE **不會回報錯誤**，一樣回「成功」，只是對方收不到（也不扣額度）。
所以程式**沒辦法知道私訊有沒有真的送到**。如果要改用私訊提醒，一定要：

1. 請每位同工先加機器人好友；
2. 讓 Webhook 一直開著，程式才能從「加好友／封鎖」事件記錄誰收得到、誰收不到。

LINE 也沒有「查詢某人是不是好友」的功能，只能靠這兩個事件自己記錄。

## 6. 怎麼算錢（則數）

| 發送方式 | 一次算幾則 | 例子 |
|---|---|---|
| 推播到群組 | 群組**人數**（不含機器人） | 30 人的群組推 1 次 = 30 則 |
| 私訊一個人 | 1 則 | 只私訊這週服事的 8 個人 = 8 則 |
| 群組訊息裡 @ 人 | 跟一般群組推播一樣按人數，@ 不另外算 | — |
| 回覆（「/群組ID」「/我的ID」的回答） | 0 則（免費） | — |
| 被動收到別人傳來的訊息（機器人不回應） | 0 則（永遠免費，見第 4 節） | — |
| 發給收不到的人（沒加好友、封鎖） | 0 則（不扣額度，但也沒送到） | — |

**降低則數的兩個方向**（可以只做一個，也可以都做）：

1. **降低頻率**：改成每 2 週發送一次（「設定 → ② → 每幾週發送一次」），大約可以**省一半**。
   ⚠️ 這裡有個常見誤解要澄清：**發送的頻率**才會影響則數，跟「訊息內容涵蓋幾週」沒有直接關係——
   如果還是每週發、只是內容多顯示未來 2 週的服事，則數並不會變少（因為 LINE 是按「發送這個動作」的對象人數算，跟內容長短無關）。
   要真的省錢，發送次數本身要變少，所以本程式提供的是「每幾週真的只發一次」的排程選項，不是「內容涵蓋幾週」。
2. **改成只私訊當週服事的人**（還沒開發，見第 6 節）：40 人群組每週發 → 每月約 160～200 則；改成只私訊 8 位當週同工 → 每月約 32～40 則。代價是每個人都要加機器人好友、Webhook 要一直開著。

完整費用與報帳資訊見 [LINE_PRICING.md](LINE_PRICING.md)。

## 7. 本程式現在做到哪裡、之後可以做什麼

| 功能 | 現在 | 需要 Webhook 一直開著嗎 |
|---|---|---|
| 每週（或每 N 週）推播到群組 | ✅ 已完成 | 不需要 |
| 「/群組ID」「/我的ID」指令、被邀進群組自動登記、被踢出群組通知管理員 | ✅ 已完成 | 抓 ID 的時候暫時開著就好 |
| 在群組訊息裡 @ 服事的人 | ✅ 已完成（同工名單要填 userId） | 不需要 |
| 自動記錄「在群組講過話／新加入」的人（名字 + ID），在「🙋 人員」頁一鍵對應 | ❌ 還沒做 | 需要（而且要一直開著） |
| 只私訊當週服事的人（省額度） | ❌ 還沒做 | 需要（要追蹤誰加了好友，且要一直開著） |
| 列出群組全部成員 | ❌ 需要認證帳號 | — |

> 「一直開著」代表需要一個**固定**的公開 https 網址（cloudflared 的臨時網址每次重開都會變），
> 通常要放到雲端主機，或用 cloudflared 的固定通道（需要 Cloudflare 帳號和網域）。這是做上面兩個新功能之前要先決定的事，**目前不做也完全不影響每週提醒的核心功能**。

## 8. 個資提醒

userId、顯示名稱都是個人資料。建議：

- 先在群組說明「機器人會記錄 ID，只用來提醒服事」；
- 同工名單只存在教會那台電腦（`config/members.csv`，不會上傳到 git），不要外流。

## 資料來源（LINE Developers，2026-09-11 查詢）

- [Messaging API reference](https://developers.line.biz/en/reference/messaging-api/)：
  - Send push message：可以發送的條件；對沒加好友、封鎖、刪除帳號的人發送會回 200 但收不到
  - Get group chat member user IDs：只開放給認證／優質帳號
  - Get group chat member profile：同群組成員不管有沒有加好友都查得到
  - Get number of users in a group chat：人數不含機器人
  - Webhook event objects：群組訊息的 `source.userId` 只在訊息事件、而且只有手機版使用者才有；`memberJoined`／`memberLeft` 事件
- [Consent on getting user profile information](https://developers.line.biz/en/docs/messaging-api/user-consent/)：手機版使用者開始使用 LINE 時就同意了；只用電腦版的人無法同意
- [FAQ](https://developers.line.biz/en/faq/)：userId 和 LINE ID 不同、依 Provider 不同（同一 Provider 底下的 Channel 共用同一組 userId）；發給收不到的人不計費；沒有查詢是否為好友的功能；無法列出機器人所在的群組
